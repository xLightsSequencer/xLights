## Notes

**Status counts (113 rows):** ✅ 33 · 🟡 19 · ❌ 51 · 🚫 0 · 🔵 2 · ➖ 8.

**Structural observations**

- *There is no preferences surface on iPad.* Desktop concentrates 100+ settings behind one `⌘,` dialog with 11 named pages. The iPad equivalents are spread across six unrelated places: a screen titled "Folders" (`FolderConfigView.swift`) reachable only from a toolbar gear in the sequence picker, the sequencer options menu, a gear menu inside the Check Sequence sheet, the Layout editor's global-output panel and canvas menu, the per-sequence `SequenceSettingsSheet` (which owns the global autosave interval), and the iOS Settings app. Users cannot find a setting by looking for it; they have to already know where it lives. This is the single largest gap in the theme and it is a placement problem before it is a missing-feature problem — 33 settings already reach parity and simply are not discoverable, and another 20 are partially there.
- *Key naming has already drifted.* iPad's `renderOnSave` gates the FSEQ write (rows 32/34), which is desktop's *Save FSEQ File On Save*; desktop's actual *Render on Save* has no iPad counterpart. `pasteByCell` (row 31) is a different axis from desktop's *Paste As*. Any future shared-settings work has to reconcile these before it can key off common names.
- *Color Manager is desktop-only by construction.* `ColorManager` lives in `src-ui-wx/color/`, so the iPad hand-copies defaults in three places (`Bridge/iPadRenderContext.cpp:478-505`, `Metal/XLMetalBridge.mm:3612-3616`, `SequencerViewModel.swift:1073-1075`), each with a comment pointing back at `ColorManager.h`. Six of 38 colors are honoured, all read-only. Moving `ColorManager` into `src-core/` (it already depends only on `xlColor`, pugixml, and `BaseSerializingVisitor`, plus one `wxSystemColour` field for system-color fallback) would fix rows 56-60 wholesale and remove three copies of the default table.
- *Keyboard bindings are structurally different, not just less complete.* Desktop bindings are user data in `xlights_keybindings.xml` with scopes and three parameterised binding kinds (insert effect / insert preset / apply settings). iPad shortcuts are compile-time `.keyboardShortcut` declarations, and `KeyBindingsSheet.swift` is a hand-maintained duplicate that will silently drift from `XLightsCommands.swift` (its own header comment at `:8-9` acknowledges this). Making the sheet generate itself from the command registry is a cheap first step and removes a live correctness hazard; making bindings editable is a much larger project.
- *Settings storage is fully duplicated.* `src-core/settings/XLightsSettings` is wx-free and could serve both clients, but `src-iPad/` never references it — every preference is re-declared as an `@AppStorage` key with a different name. There is consequently no path for a settings export/import between the two clients.

**Two desktop-side bugs found while auditing (not parity issues)**

- `OtherSettingsPanel::TransferDataFromWindow` never calls `SetLinkedControllerUpload` — the "Link controller upload" choice is loaded (`OtherSettingsPanel.cpp:338`) but a user's change is discarded. `xLightsFrame::SetLinkedControllerUpload` is declared at `xLightsMain.h:1229` and has no definition anywhere in the tree.
- `ViewSettingsPanel::TransferDataToWindow` never restores `CheckBox_ZoomMethod` — it is written on OK (`ViewSettingsPanel.cpp:193`) but always reopens showing its constructor default of `true` (`:105`), so a user who turned "Zoom To Cursor" off silently turns it back on the next time they open Preferences and press OK.

**Suggested porting order within this theme**

1. Add a real Settings entry point — a `Settings…` menu item bound to `⌘,` plus a sectioned screen that absorbs the 33 settings that already exist but are scattered (rows 14, 16, 20-30, 33-43, 48-54, 65, 75, 80, 103-105, 110). Pure re-hosting, no new behavior, and it makes the remaining gaps visible to users and to us. *(Decision history: declined 2026-06-11 in favor of context sheets; **redo approved 2026-08-01** — some settings genuinely belong in a global settings surface, and placement plus key naming need cleanup. See `00-overview.md` §Decisions.)*
2. Generate `KeyBindingsSheet` from the command registry instead of the hand-written table (row 91) — removes an active drift hazard.
3. Fill in the cheap missing toggles that already have a working core path: Node Values (22), Group Effect Indicator (23), Default View for New Sequences (36), Prompt issues during batch render (74), Controller ping interval (82). Each is a single `@AppStorage` key plus one call site.
4. Promote the Output settings (44-46) out of the Layout editor into the new Settings screen so they sit where desktop users expect them.
5. Move `ColorManager` to `src-core/` and add a color editor (56-64). Largest item in the theme; unblocks six rows and deletes three hand-copied default tables.
6. Backup settings (2-7) — decide first whether iPad backup should become a show-folder backup like desktop's, or stay a sequence-file snapshot. The answer determines whether four of those rows are portable at all.
