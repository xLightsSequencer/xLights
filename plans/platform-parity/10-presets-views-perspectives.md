## Notes

- **Row counts:** ✅ 45 · 🟡 14 · ❌ 25 · 🚫 4 · 🔵 3 (91 rows).
- **The one data-loss bug in this theme is row 71.** The iPad reads `<views>` out of `xlights_rgbeffects.xml` at show load but has no writer for it, so every view create/rename/clone/delete/membership edit made in `DisplayElementsSheet` evaporates on relaunch. This was verified by tracing the code that *would* save: all three rgbeffects writers in `iPadRenderContext.cpp` were read end to end and none touch a `views` node. The fix is small and self-contained — a `SaveViews()` mirroring `SaveViewpoints()` (`src-iPad/Bridge/iPadRenderContext.cpp:508-544`), plus a dirty flag set by the `addView/deleteView/renameView/cloneView/addModel…` family in `XLSequenceDocument.mm:3436-3700`. Do this first; the rest of the Display Elements port is otherwise the strongest area in this theme.
- **Jukebox is a clean, self-contained port opportunity.** The data model already lives in wx-free core (`src-core/render/JukeboxButtonData.h`, load/save in `SequenceElements.cpp:846` / `SequenceFile.cpp:1541`) and round-trips through an iPad save untouched. What is missing is purely UI plus a thin bridge: a button-grid sheet, `SelectEffectUsingDescription` / `SelectEffectUsingElementLayerTime` equivalents, and a looped-playback call. Nothing here is iPadOS-restricted.
- **Preset interchange is asymmetric and should be fixed together.** Desktop exports `.xpreset` (XML, root `<preset>`) and imports `.xpreset` + rgbeffects XML; iPad exports the whole library as JSON and imports rgbeffects XML only. Neither side can read the other's export. Two small changes close it: teach `importPresetsFromPath:` to accept a `<preset>` root (`XLSequenceDocument.mm:19680-19688`) and widen the `fileImporter` content types (`PresetBrowserSheet.swift:261-263`); then add a subtree `.xpreset` export path.
- **Perspectives are correctly absent, not merely unported.** They are a serialization of wxAUI dock geometry, which has no meaning in a SwiftUI layout, so rows 74-79 are marked ❌ rather than 🚫 only because the *user-facing* idea (named, recallable workspace layouts) is portable even though the stored format is not. The important thing — that an iPad save does not clobber the desktop's saved perspectives — already holds (row 80), because the iPad patches the rgbeffects XML surgically instead of regenerating it.
- **Suggested porting order within this theme:** (1) view persistence, row 71; (2) preset import/export interchange, rows 24 & 26; (3) Master-View member reorder, row 54 — the Sort menu already proves the underlying `moveTopLevelElement(named:beforeNamed:)` plumbing works, so this is UI-only; (4) `FixRgbEffects` on load, row 16 — a one-line call; (5) jukebox, rows 32-40; (6) the small preset-browser gaps (Top/Bottom, sort, forbidden-character validation), rows 15/18/23.
- **Structural observation:** the preset and Display Elements bridges (`XLSequenceDocument.h:3639-3846` and `:903-1075`) are unusually complete — most remaining gaps in this theme are missing SwiftUI affordances over bridge methods that already exist, not missing bridge coverage. The exceptions are view persistence (no writer at all), rgbeffects view import (row 62), and everything jukebox.
