## Notes

- **The theme splits cleanly in two.** AI is at near-parity — both hosts construct the same `ServiceManager` over the same six built-in providers, and the iPad reaches every capability (`PROMPT` indirectly, `COLORPALETTES`, `IMAGES`, `MAPPING`, `SPEECH2TEXT`) through real UI. Automation and scripting are at **zero** parity: 101 of the 151 rows are 🚫, and every one of them traces to two structural facts — no HTTP listener and no embedded script interpreter on iOS.
- **The `ServiceProperty` abstraction is the reason AI ported so well.** `src-core/ai/ServiceProperty.h` is pure data; `PropertyGridBuilder.cpp` and `AIServicesSettingsSheet.swift:159-210` are independent renderers of the same vector. A new provider or a new setting lands on both platforms with no bridge work. The one leak is row 27: `AIImageGenerationSheet.swift:199` filters to `.choice` only instead of rendering all kinds the way the settings sheet does, so `OpenAIImageGenerator`'s `Kind::String` model fallback is invisible on iPad. That is a five-line fix and the highest value-per-effort item in the theme.
- **Bridge gaps are narrow and specific.** Only three exist: the palette description is dropped because `XLAIServices.h:164-168` never carries it (row 23); there is no `AddEmbeddedImage` wrapper, so iPad-generated images land as loose files instead of inside the `.xsq` (row 34); and `XLImportSession.mm` exposes only `GenerateModelMapping`, not `CallLLM`, so the four-pass prompt fallback can't run (row 41). Row 41 is the one users will actually hit — with ChatGPT or ollama configured (neither declares `MAPPING`), the iPad's AI Map button disappears entirely while the desktop still maps.
- **Suggested porting order within this theme:** (1) row 27, render all property kinds in the image sheet; (2) row 34, add an embed-into-sequence path so iPad-authored sequences stay self-contained — this is a correctness issue, not a convenience one, since a sequence moved off the iPad loses its images; (3) row 41, bridge `CallLLM` and port the four mapping passes; (4) row 35, add the AI button to `MediaManagerSheet.swift`; (5) rows 23 and 30, both small.
- **Reverse-parity candidates.** The iPad's async service Test (row 16), palette generation off the UI thread (row 24), the per-service readiness banner (row 17), the third-party data disclosure (row 18), and the user-controllable black-background toggle applied on every commit (row 31) are all better than their desktop counterparts. The desktop's `AIColorPaletteDialog.cpp:136` synchronous `GenerateColorPalette` on the UI thread is a genuine freeze worth fixing by copying the iPad's shape.
- **Row 150 is the largest unclaimed opportunity in this theme.** The iPad has no App Intents / Shortcuts surface at all. It is also the only automation shape iOS actually sanctions — Shortcuts actions for "render this sequence", "upload to controller", or "open sequence" would give the iPad a legitimate automation story that the REST/Lua/xlDo stack can never have there, without violating App Store rule 2.5.2.
- **Care needed reading the desktop verb list.** `xLightsAutomations.cpp:1491-1593` is one large comment block containing 25 further `cmd == "…"` branches that all return 504. Grepping for `cmd ==` without checking compilation status inflates the verb count by half; only lines 110-1400 are live (row 104 records the dead set).
- **`importSequence` is not a verb; `importXLightsSequence` is.** A `cmd == "importSequence"` branch exists at `xLightsAutomations.cpp:1582` but sits inside the dead comment block (row 104), so it is never compiled. The live batch-import path is `importXLightsSequence` (`:1163-1189`, row 98), which is what the shipped `resources/scripts/BatchImportSequences.lua:86` actually calls. Any doc or issue citing an `importSequence` automation command is describing the dead branch.
- **`runScript` runs Lua only.** Despite `ScriptsDialog.cpp:260-270` dispatching both `.lua` and `.py`, the `runScript` automation verb hardcodes `LuaRunner` (`xLightsAutomations.cpp:865-866`). Python is reachable only from the interactive dialog — and per the platform table, only on Windows.
