## Notes

- **Structure.** The colour panel is the one settings panel that is *mostly* shared: desktop's `ColorPanel` is a `JsonEffectPanel` over `resources/effectmetadata/shared/Color.json`, and the iPad reads the very same JSON, so the Brightness / Contrast / HSV sliders, their value curves, the "Adjustment" section and the `BrightnessLevel` legacy key are parity-by-construction. Everything that diverges lives in the five `controlType: "custom"` rows, which each platform hand-builds.
- **Curve cores are genuinely shared.** `XLValueCurve` and `XLColorCurve` wrap `src-core/render/ValueCurve.{h,cpp}` and `ColorCurve.{h,cpp}` directly, so serialisation is byte-identical in both directions. The parity gaps below are UI-surface gaps, not format gaps — with one exception: `XLColorCurve` exposes no `type` accessor (row 77), so the ColorCurve *blend mode* is a format field the iPad can round-trip but never read or write.
- **Biggest structural gap: no editor-scoped Cancel.** Both iPad curve editors persist on every keystroke and offer only "Done" (rows 79, 80, 104, 120). Desktop keeps a `_backup` copy plus a point-level undo stack in each dialog. The iPad is not undo-less — every curve mutation routes through `SequencerViewModel.setSettingValue`, which registers an app-level undo step (`src-iPad/App/SequencerViewModel.swift:3649-3655`) — so the genuinely missing piece is a *session-scoped* revert, not undo itself. A snapshot on sheet-open plus a Cancel button is the change with the widest blast radius, and would also let the "discard current curve?" preset confirmations (rows 86, 115) be added cheaply.
- **Bridge gaps that block features outright:** (a) `XLColorCurve` needs a `type` property (`ColorCurve::SetType`/`GetType`) before row 77 can be built; (b) `XLValueCurve.reload(fromSerialised:)` should take the host property's min/max/divisor and run `SetLimits` + `FixChangedScale` the way `ValueCurveDialog::OnButtonPresetClick` does, or preset loading silently mis-scales (row 114); (c) `savedPalettes` should also scan the show-folder root and accept `.scss` to match desktop discovery (rows 31, 32).
- **The two "dropper" panes (rows 37, 121) are the largest missing surface** and both hinge on drag-and-drop, which the iPad has none of for colours or curves (rows 35, 36). A SwiftUI `draggable`/`dropDestination` pair on the palette rows and the VC buttons would unlock all four rows at once; the clipboard paths already prove the payload formats work.
- **Watch the two iPad-only value-curve controls.** Editable Min/Max (row 111) and the "Real Values" toggle (row 112) have no desktop counterpart, and both are hazardous: Min/Max can desynchronise a curve from its host slider's declared range, and Real Values cannot be switched back off because core exposes only `SetRealValue()`. Per project convention these should either be removed or be given a desktop counterpart before they generate cross-platform bug reports.
- **First-run divergence is worth fixing early** (rows 5, 6): different default palette colours *and* a different default-enabled slot set means the same "drop a new effect" gesture produces visibly different output on the two clients. This is a two-line fix on the iPad side.
- **Suggested porting order within this theme:** (1) rows 5–6 default palette alignment — trivial, user-visible; (2) rows 79/80/104/120 editor snapshot + revert, then 86/115 confirmations on top; (3) row 77 ColorCurve type bridge + picker; (4) row 114 preset rescale (correctness); (5) rows 95/99/102 typed entry and the audio-track picker; (6) rows 35/36/37/121 drag-and-drop plus the two dropper panes; (7) rows 13/43/52 lock buttons together with row 55 palette randomisation, which is what makes locks meaningful.
- **Out of scope, noted for the right owner:** `src-ui-wx/color/ColorManager.{h,cpp}` (UI theme colours) → theme 11; `src-ui-wx/color/DimmingCurvePanel.{h,cpp}` (per-model output dimming curves, unrelated to value curves) → theme 06; `src-ui-wx/effectpanels/MovingHeadPanels/MHColorPanel.h` (moving-head effect colour wheel) → theme 04; `src-iPad/App/EffectPaletteView.swift` is the effect-type dropper, not a colour palette → theme 02.
