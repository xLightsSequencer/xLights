## Notes

- **The one hard restriction in this theme is VAMP** (rows 18-21). It is not a porting backlog item: `src-core/media/AudioManager.cpp:1918-2072` fences the entire host behind `#if !TARGET_OS_IPHONE`, and the underlying blocker — plugins are third-party `dlopen`ed shared libraries — is an iOS platform rule, not an xLights limitation. The iPad already substitutes hand-written detectors (`OnsetDetector`, `TempoDetector`, `ChordDetector`, `PitchDetector`, `SoundClassifier` — all included at `src-iPad/Bridge/XLSequenceDocument.mm:46-50`) covering the three built-in analyses. The genuinely lost capability is **Polyphonic Transcription** (note-level timing from audio), which has no non-VAMP implementation on either platform. The only other restricted item is the zipped `.mxl` MusicXML container (row 166), which is a wx-zip dependency rather than an iOS rule.

- **Keyboard-driven timing entry is the biggest real gap** (rows 58, 60, 61, 50, 51, 147, 148). The desktop's `TIMING_ADD` ("t") / `TIMING_SPLIT` ("s") during playback is the fastest way to lay a timing track by hand, and the iPad has no equivalent — `src-iPad/App/XLightsCommands.swift` defines no timing commands and `src-iPad/App/KeyBindingsSheet.swift:49` lists only the nudge pair. Since iPads routinely run with a hardware keyboard (Magic Keyboard), this is worth a `.keyboardShortcut` on a new "Add Mark at Play Marker" command wired to the existing `addTimingMark` (`src-iPad/App/SequencerViewModel.swift:5049`) and `splitTimingMark` (`:5071`) — both already exist and are undo-wired. **Highest value / lowest cost item in this theme.**

- **Selection-scoped lyric breakdown is missing** (rows 98, 100, 101). The iPad bridge has `breakdownPhraseAtRow:atIndex:` (`src-iPad/Bridge/XLSequenceDocument.h:880`) but no word-level or selection-level counterpart, so a user who wants to re-break three specific words must redo the whole track. Adding `breakdownWordAtRow:atIndex:` plus a loop over the current selection is a small bridge + VM change on top of `src-core/lyrics/LyricBreakdown.cpp:60`.

- **The user-dictionary editor is the weakest single iPad surface** (rows 109, 111, 112, 113). Desktop validates every phoneme against `phoneme_mapping` before saving and warns on main-dictionary overrides (`src-ui-wx/sequencer/LyricUserDictDialog.cpp:242`, `:363`, `:197`); the iPad sheet saves free text unchecked (`src-iPad/App/UserLyricDictionarySheet.swift:87-105`). An invalid phoneme there produces a silently broken singing face rather than an error. `PhonemeDictionary::ContainsPhonemeMap` (`src-core/lyrics/PhonemeDictionary.h:36`) is already wx-free — this only needs a bridge accessor and a disabled Save button.

- **Alt-track playback divergence** (row 125) is a behaviour trap, not just a missing control: the same sequence, with the same track selected, plays different audio on the two clients. Desktop routes playback through `xLightsFrame::GetPlaybackAudio()` (`src-ui-wx/xLightsMain.cpp:2388`); the iPad has no such indirection and the code comments the difference as intentional. Worth either matching it or renaming the iPad control so it reads as display-only.

- **Structurally, the iPad's timing surface is well factored.** `AddTimingTrackSheet.swift` unifies what the desktop spreads across `NewTimingDialog`, `MetronomeLabelDialog`, `NoteImportDialog`, `LRCLIBSearchDialog`, `LyricsDialog` and two separate row-menu entries, and the desktop actually has the *worse* duplication — Sequence Settings → Timings → New (`src-ui-wx/sequencer/SeqSettingsDialog.cpp:1113`) is a second copy of the add-track flow that silently omits Audio Onsets/Tempo/Chords and AI Lyrics, and always analyses the main track rather than the selected one. That desktop inconsistency is worth fixing independent of parity.

- **Suggested porting order within this theme:** (1) keyboard timing-mark add/split + the divide keybindings; (2) user-dictionary phoneme validation; (3) selection-scoped phrase/word breakdown (rows 98/100/101); (4) activate-after-import (row 89) and the frame-rate-aware preset filter (row 6) — both one-liners; (5) alt-track playback routing (row 125) and the single-active-timing divergence (row 49); (6) audio pad/trim (row 121) and legacy `.xml` timing import (row 87). "Generate Lyrics From Data" (row 41) and "Prepare Audio" (row 156) are legacy/desktop-workflow features that can stay unported without a user-visible parity complaint.
