## Notes

- **The single biggest structural gap is the missing cell range.** Desktop's `mCellRangeSelected` / `mRangeStartCol..mRangeEndCol` (`src-ui-wx/sequencer/EffectsGrid.h:418-425`) is the substrate for paste-into-a-region, Create Random Effects, keyboard column navigation, and the enable/disable state of half the grid context menu. The iPad marquee (`src-iPad/App/EffectsMetalGridView.swift:1569`) only ever produces a set of existing effects, so rows 12, 43 and 95 all fail for the same underlying reason. Porting the cell range would be the highest-leverage single change in this theme.
- **Two undo stacks.** The iPad grid runs on Foundation's `UndoManager` with snapshot closures (`src-iPad/App/SequencerViewModel.swift:18`) while a handful of bridge operations still drive the shared core `UndoManager` (`src-iPad/Bridge/XLSequenceDocument.mm:1440`, `:19064`), which is cleared on open (`:850`). Any future op implemented at the bridge level will land on the wrong stack and undo out of order. Worth deciding on one owner before adding more mutating bridge calls.
- **Several capable operations are gated behind hardware that most users will not have.** Ctrl/Shift-click multi-select needs a Magic Keyboard (`EffectsMetalGridView.swift:1274`), and butt-up shared-edge resize needs an Apple Pencil Pro squeeze (`:1712`). Both deserve touch-reachable fallbacks (a long-press "Add to Selection", a menu entry for shared-edge resize) before they count as parity.
- **No drop target exists on the grid canvas at all.** That single absence covers both drag-from-effect-list (#35) and external media drop (#36). Adding one `dropDestination` on the effects canvas would close two rows and bring the iPad in line with how every other iPadOS timeline app behaves.
- **Menu placement drifts.** Many operations exist on iPad but under a different surface than on desktop — global visibility toggles moved from the row menu to a "View" corner menu (#119, #124-126), Add/Import Timing Track moved off the timing-row menu (#141, #143, #146, #148), and Edit Display Elements is reachable only from empty space below the rows (#150). None of these are missing functionality, but a desktop user switching over will hunt for them. Consider mirroring the desktop grouping onto the row context menus, which are already long enough to absorb the entries.
- **Suggested porting order within this theme:** (1) cell-range selection and its three dependent features; (2) a grid drop target for palette drag and external files; (3) touch-reachable multi-select; (4) empty-cell context menu (#95) and double-click-to-pick-an-effect (#38), which together are how a keyboard-less user discovers the grid; (5) scroll-selection-into-view (#15), cheap and immediately noticeable; (6) the timing-mark clipboard and lock entries (#103, #104).
- **Out of scope but adjacent:** the AC mode gap (#181) is large enough that it may deserve its own decision record rather than a single row — it is a whole second editing modality (paint on/off/shimmer/twinkle with ramps, fill and cascade tools) with its own toolbar and its own keyboard handler, and nothing in `src-iPad/` references it.
