## Notes

- **The iPad is overwhelmingly a mirror, not a superset.** A mechanical diff of all 1,413 quoted UI labels in `src-iPad/App/*.swift` against the full `src-ui-wx/` + `src-core/` string corpus flagged 540 labels with no desktop match, yet semantic verification reduced that to the eight 🔵 rows originally listed (1-8). Label divergence is almost entirely wording, not capability.
- **Label diffing has a systematic blind spot, which rows 19-48 fill.** A gap only surfaces in a label diff if the iPad spells it as a *string*. Everything that differs in **behaviour behind an identically-named control** is invisible to that method — snapping vs. not snapping, looping vs. playing once, filtering a list vs. scrolling it, repacking on save vs. refusing to save. Rows 19-48 were recovered by cross-checking the previous reverse-parity plan (`plans/ipad-parity/14-reverse-parity-ipad-only.md`) claim-by-claim against current code, and every one of them is a behavioural gap with no distinguishing label. Three of them (rows 19, 24, 41) are **core APIs with no `src-ui-wx/` caller at all** — `SequencePackage::Repack`, `UDController::ExportAsJSON`, `UndoManager::SetMaxSteps` — the same shape as row 1's `RemoveUnusedMedia`, and the single most reliable signature of a reverse-parity gap in this codebase.
- **Four claims from the older plan were re-verified as closed on desktop and are deliberately *not* rows here.** (a) *Edge auto-scroll while dragging* — desktop pans on all four edges via `mScrollTimer` armed in `UpdateEffectMoveDragState` (`EffectsGrid.cpp:8536-8545`, `zone = FromDIP(40)`, handler `:8335-8396`); the only residue is that `ResizeSingleEffectMS` (`:6810`) never arms it, so resize-drags don't auto-scroll. (b) *Live invalid-drop red tint* — `DrawEffectMoveDragOverlay` (`:8625`) uses `fillCollide(200,40,40,100)`/`borderCollide` (`:8632`) driven by `mEffectMoveHasCollision` (`:8520`), plus a no-entry cursor (`:8521`). (c) *Double-click empty cell → gap-filling effect* — `EffectsGrid.cpp:354` onward, with neighbour clipping via `GetEffectBeforeEmptyTime`/`GetEffectAfterEmptyTime` (`:384-395`); desktop shows the effect wheel where iPad uses the armed palette effect. (d) *Cursor drag readout including fade seconds* — desktop builds `" fadein: %.2fs"` / `" fadeout: %.2fs"` at `EffectsGrid.cpp:7035-7042` and shows it live during fade drags (`:6836`); only the presentation differs (status bar, not a cursor-anchored pill). The older plan's "desktop omits fade seconds entirely" is false against current code.
- **Fade-time drag on the grid is confirmed present on desktop**, so it correctly appears nowhere on this scorecard: `FADE_IN_HANDLE`/`FADE_OUT_HANDLE` (`EffectsGrid.h:49-50`), hit-test `EffectsGrid.cpp:2085-2107`, write-back to `T_TEXTCTRL_Fadein`/`Fadeout` at `:6819-6836`, `DrawFadeHints` at `:7777` (called `:7734`), gated by `IsSuppressFadeHints()`.
- **Reusing an up-to-date `.fseq` on open is also already desktop behaviour**, contrary to the older plan: `xLightsFrame::OpenSequence` (`SeqFileUtilities.cpp:262`) defines `readFseqData` (`:383-414`) and calls it whenever the fseq exists (`:419-425`), and the only `RenderAll()` on that path (`:576`) is gated on `WasConverted()`. What desktop lacks is the *freshness* guard — it validates channel/frame counts (`:604-618`) but never compares mtimes, so it will happily load a stale fseq. That is a correctness nit for theme 09, not a reverse-parity feature.
- **Label diffing produces false positives at a high rate — every row here was re-verified semantically.** Examples that looked iPad-only and are not: "Render Loop Region" is desktop's `"Render Selected Region"` (`Waveform.cpp:254`); "Switch Temporarily…" is desktop's `"Change Temporarily"` (`ShowDirectoriesDialog.cpp:74`); "Bulk Find Missing…" is `"Bulk Find Images..."` (`ManageMediaPanel.cpp:1462`); "Convert Effects on Layer to 'Per Model'" is `"Convert Effects to 'Per Model'"` (`RowHeading.cpp:777`); "Auto-Label Marks" is `AutoLabelDialog`; "Upload All…" is `MultiControllerUploadDialog`; "Export Connections…" is `ID_MNU_EXPORT_CONTROLLER_CONNECTIONS` (`xLightsMain.cpp:1036`); "Auto Update On Open" is `"Auto Update On Load"` (`ShowDirectoriesDialog.cpp:109`); "Apply Selected Effect's Palette" is `"Apply Selected Effect Palette to Region"` (`TimeLine.cpp:299`).
- **Three features that read as iPad-first are in fact desktop-first, with the iPad consuming shared core.** LRCLIB lyric search (`src-iPad/App/LRCLIBClient.swift` vs `src-ui-wx/sequencer/LRCLIBSearchDialog.cpp`), the music/lyrics vendor catalog (`src-iPad/Bridge/XLMusicCatalog.mm` vs `src-ui-wx/import_export/VendorMusicDialog.cpp` — note the shared `src-core/import_export/MusicCatalog.cpp` currently has **no desktop caller**, so desktop still runs its own older implementation), and speech-to-lyrics (both gate on `aiType::SPEECH2TEXT`; desktop at `RowHeading.cpp:801`, iPad at `AddTimingTrackSheet.swift:499`).
- **AI: no reverse-parity gap.** Every iPad AI sheet has a desktop counterpart — `AIImageGenerationSheet.swift` ↔ `src-ui-wx/ai/AIImageDialog.cpp`, `AIPaletteGenerationSheet.swift` ↔ `src-ui-wx/ai/AIColorPaletteDialog.cpp`, `AIServicesSettingsSheet.swift` ↔ `src-ui-wx/ai/PropertyGridBuilder.cpp` + `WxServiceSettingsStore.cpp`. All share `src-core/ai/ServiceManager`. Answer for the AI theme owner: **no**, nothing AI-related belongs on this scorecard.
- **`MusicCatalog` is a latent consolidation opportunity, not a feature gap.** The wx-free `src-core/import_export/MusicCatalog.cpp` was written for the iPad bridge; pointing `VendorMusicDialog` at it would delete a duplicate implementation without changing user-visible behavior.
- **Infrastructure with no user-facing surface was excluded**, per scope: `XLLaunchTiming`, `EffectIconCache.swift` (desktop has its own `src-ui-wx/effectpanels/EffectIconCache.cpp`), `GridMetrics`, `RowsScrollState`, `SyncedScrollView`, `ScrollbarOverlay`, `XLGridMetalBridge`, `xlStandaloneMetalCanvas`, and `EditableNumberField` (a numeric-entry idiom, not a capability).
- **One reverse-direction item routed to theme 07, not tracked here.** The older plan carried a "Layout editor Controllers tab — present on desktop, intentionally omitted on iPad" row. That is desktop-ahead, so it never belonged on this scorecard, and it is also **no longer true**: `LayoutSidebarTab` includes `.controllers` (`src-iPad/App/LayoutEditorView.swift:54`, label `:61`, icon `:69`) with a filter and cached roster added under J-31 (`:276-285`). The `J-5` comment at `:49-52` still says the tab is omitted and is now stale. Upload/Visualize actions behind it are still placeholders (`pendingControllerActionAlert`, `:284-286`) — that residual belongs on theme 07's scorecard.
- **Verification method.** Each 🔵 claim required the desktop search to be able to come back positive: greps were run with `grep -E` alternation (an early pass using `\|` inside `-E` silently matched literal pipes and produced false "absent" results — those were re-run), and negative results were corroborated by sweeping every quoted string in the relevant desktop file rather than trusting a single term. Row 7 in particular started as a much larger claim ("desktop never prompts on file pick") and was cut down to its true scope after `BulkEditControls.cpp:188-200` turned up.
