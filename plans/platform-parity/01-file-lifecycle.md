## Notes

- **The single largest gap is show-folder-level backup.** The iPad's "backup" is a 20-deep snapshot ring of the *current sequence file only* (`src-iPad/App/SequencerViewModel.swift:1861-1909`). Desktop backs up the entire show folder — controllers, models, views, presets, keybindings, and every sequence — on demand (F10), on launch, on save, and to an alternate location, with age-based purging. Restore is correspondingly narrower: rows 108–110 show the iPad cannot restore `xlights_networks.xml`, `xlights_rgbeffects.xml`, `xlights_effectpresets.json` or `xlights_keybindings.xml` at all. A user who corrupts their layout on the iPad has no recovery path. This is the highest-value item in the theme and it needs no new UI paradigm — `writeSaveBackup` already knows the show folder.

- **Data Layers are entirely absent** (rows 51, 121, 162, 163). This is a coherent feature cluster — `DataLayerSet` (`src-core/render/DataLayer.h:58-75`) is wx-free and already linked by the iPad; what is missing is the converter plumbing (`FileConverter::ReadLorFile` and friends, currently reached only from `src-ui-wx/sequencer/SeqSettingsDialog.cpp:1352-1468`) and a bridge surface. Because the "Nutcracker" layer already backs the Erase/Canvas render mode the iPad *does* expose (`src-iPad/Bridge/XLSequenceDocument.mm:1049-1058`), the data model is half-wired already.

- **Autosave is sequence-only.** Rows 95–96: the iPad autosaves the `.xsq` but never `xlights_rgbeffects.xml` or `xlights_effectpresets.json`, and has no recovery prompt for either. Layout edits made on the iPad are protected only by explicit saves. This pairs naturally with the backup work above.

- **Frame-interval changes are unsafe on iPad** (row 146). `setFrameIntervalMS:` (`src-iPad/Bridge/XLSequenceDocument.mm:1025-1033`) rewrites the timing string without the desktop's save/close/reopen cycle that snaps existing effects to the new grid. On a sequence that already has effects this silently leaves them off-grid. Either port the reopen cycle or restrict the picker to empty sequences.

- **The iPad is stricter than desktop about media location and looser about sequence location.** `MediaRelocation` refuses to store a path outside the show/media folders and offers no "embed" alternative (row 136), while Save As merely warns when a sequence lands outside the show folder (row 75) where desktop hard-refuses. Both divergences are deliberate per their code comments, but they are inverted relative to each other and worth a consistency decision.

- **Two structural bridge gaps** underlie several rows: there is no bridge call to enumerate or restore show-folder configuration files (rows 100, 104, 108), and no bridge call for the legacy sequence converters (rows 44, 51, 60, 162). Both are `src-core`-side work that the desktop already exercises; neither needs new core code.

- **Suggested porting order within this theme:** (1) show-folder backup + restore of config files, since it is the only data-loss-shaped gap; (2) rgbeffects/presets autosave and their recovery prompts, which reuse the same file-set enumeration; (3) frame-interval reopen cycle, a correctness fix; (4) the missing Sequence Settings affordances that are pure UI — Adjust Milliseconds (147), metadata link buttons (152), and the no-media warning (150); (5) Data Layers, the largest and least urgent block. Cheap adjacent fixes: gate the iPad's base-folder merge the way desktop does (row 179, one predicate call) and drop the broken-only restriction on Bulk Find (row 132).

- **Reverse-parity candidates worth pulling to desktop:** remove-unused-media (row 133), pre-restore safety snapshot (112), recent-list pruning and per-entry removal (20, 21, 39), and timing-track export from the settings dialog (158). None of these depends on iOS. (Bulk find and reload-from-disk were on this list until the 2026-08-01 cross-check found both already on desktop — rows 132 and 134; the live gap on 132 now runs the *other* way, since desktop can bulk-repoint working files and the iPad only broken ones.)
